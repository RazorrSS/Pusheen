## Кодекс поведения

Этот проект и все, кто участвует в нем, должны соблюдать наш [Кодекс поведения](./CODE_OF_CONDUCT.md). Участие предполагает согласие с его положениями.

## Начало работы

### Предварительные требования

- Git установлен на вашем компьютере
- Учетная запись GitHub
- Необходимые инструменты разработки (Node.js, Python и т.д. в зависимости от проекта)

### Установка локальной среды

1. **Сделайте форк репозитория**
   ```bash
   Нажмите кнопку "Fork" на GitHub
   ```

2. **Клонируйте ваш форк**
   ```bash
   git clone https://github.com/ваше-имя/репозиторий.git
   cd репозиторий
   ```

3. **Добавьте upstream репозиторий**
   ```bash
   git remote add upstream https://github.com/оригинальный-репо/репозиторий.git
   ```

4. **Установите зависимости**
   ```bash
   npm install
   # или
   pip install -r requirements.txt
   ```

## Процесс разработки

### 1. Создание ветки

Всегда создавайте новую ветку для вашей работы:

```bash
git checkout -b feature/описание-функции
```

Рекомендуемые префиксы веток:
- `feature/` - для новых функций
- `fix/` - для исправления ошибок
- `docs/` - для документации
- `refactor/` - для рефакторинга
- `test/` - для тестов

### 2. Работа над кодом

- Пишите чистый, читаемый код
- Следуйте соглашениям о стиле проекта
- Добавляйте комментарии только для сложной логики
- Часто коммитьте с понятными сообщениями

### 3. Тестирование

Перед отправкой PR убедитесь, что:

```bash
# Запустите тесты
npm test

# Проверьте линтер
npm run lint

# Постройте проект
npm run build
```

## Стиль кода

### Общие правила

- Используйте 2 пробела для отступов (или 4, в зависимости от проекта)
- Максимальная длина строки: 100 символов
- Используйте camelCase для переменных и функций
- Используйте PascalCase для классов и компонентов
- Добавляйте точку в конце комментариев

### Примеры

**Хорошо:**
```javascript
function getUserProfile(userId) {
  const user = fetchUser(userId);
  return user.profile;
}
```

**Плохо:**
```javascript
function get_user_profile(u_id){
let u = fetchUser(u_id)
return u.profile}
```

## Процесс коммитов

### Сообщения коммитов

Пишите ясные и описательные сообщения коммитов:

```bash
git commit -m "fix: исправлена ошибка при загрузке данных"
```

**Форматы:**
- `feat:` - новая функция
- `fix:` - исправление ошибки
- `docs:` - изменения документации
- `style:` - изменения стиля (без влияния на функциональность)
- `refactor:` - переструктуризация кода
- `test:` - добавление или обновление тестов
- `chore:` - другие изменения (обновление зависимостей и т.д.)

### Хорошие примеры сообщений

- ✅ `feat: добавлена поддержка темного режима`
- ✅ `fix: исправлена ошибка при пагинации`
- ✅ `docs: обновлена документация по установке`
- ✅ `test: добавлены тесты для функции валидации`

### Плохие примеры сообщений

- ❌ `update`
- ❌ `fix bug`
- ❌ `changes`
- ❌ `asdf`

## Pull Request

### Перед созданием PR

1. Убедитесь, что ваша ветка актуальна с upstream:
   ```bash
   git fetch upstream
   git rebase upstream/main
   ```

2. Запустите все тесты и линтеры

3. Обновите документацию, если необходимо

### Создание PR

1. Перейдите на GitHub и нажмите "New Pull Request"
2. Выберите вашу ветку для сравнения с основной веткой
3. Заполните шаблон PR со следующей информацией:

**Заголовок PR:**
```
feat: добавлена новая функция X
```

**Описание:**
```
## Описание
Кратко объясните, что делает этот PR

## Тип изменений
- [x] Новая функция
- [ ] Исправление ошибки
- [ ] Критическое изменение

## Как протестировать
1. Шаг 1
2. Шаг 2
3. Результат

## Связанные проблемы
Закрывает #123

## Контрольный список
- [x] Код протестирован локально
- [x] Тесты добавлены/обновлены
- [x] Документация обновлена
- [x] Нет новых предупреждений линтера
```

### Рецензирование

- Будьте готовы к конструктивной критике
- Отвечайте на комментарии рецензентов
- Если нужны изменения, добавьте их в новый коммит
- Не форсируйте пуш без причины

## Сообщение об ошибках

### Перед созданием issue

1. Проверьте список существующих issues
2. Проверьте документацию
3. Попробуйте воспроизвести ошибку

### Шаблон сообщения об ошибке

**Заголовок:**
```
Краткое описание ошибки
```

**Описание:**
```
## Описание
Подробное описание того, что произошло

## Шаги для воспроизведения
1. Шаг 1
2. Шаг 2
3. Ошибка происходит

## Ожидаемое поведение
Что должно было произойти

## Фактическое поведение
Что произошло на самом деле

## Окружение
- ОС: Windows 10
- Версия Node.js: 16.0.0
- Версия проекта: 1.0.0

## Скриншоты
[Если применимо]

## Дополнительный контекст
[Любая другая информация]
```

## Запрос функций

Если у вас есть идея для новой функции:

1. Проверьте, не был ли уже создан такой запрос
2. Создайте новую issue с пометкой "enhancement"
3. Опишите функцию, ее преимущества и случаи использования
4. Приветствуется создание прототипа или демонстрации

**Шаблон запроса функции:**
```
## Описание
Ясное описание желаемой функции

## Проблема
Какую проблему она решит?

## Предлагаемое решение
Как должна работать новая функция?

## Альтернативные решения
Есть ли другие способы решить эту проблему?

## Дополнительный контекст
Примеры, скриншоты, ссылки
```
